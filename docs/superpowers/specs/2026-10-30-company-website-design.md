# 软件与数字技术公司官网全栈系统设计

日期：2026-10-30

## 1. 背景与目标

从空目录搭建一个可实际运行的公司官网、管理后台与内容服务。首版内容定位为软件与数字技术公司，使用可替换的演示品牌“NEXORA / 诺川科技”。系统必须提供科技感视觉与动效、中英文自动切换、可持续保存的内容配置，以及 Logo、页脚备案信息等品牌资料管理能力。

核心目标：

- 官网具备良好首屏性能、SEO、响应式布局和中英文内容。
- 管理员无需修改代码即可维护站点资料、首页模块、解决方案、案例和新闻。
- 内容修改真实写入 MySQL，发布后官网刷新即可读取最新内容。
- 首版保持单应用部署和单管理员模型，避免不必要的微服务与权限复杂度。

## 2. 已确认的技术路线

采用 Nuxt 全栈一体化架构：

- Nuxt、Vue 3、TypeScript：官网、后台和服务端接口共用一套工程。
- Nuxt SSR：官网服务端渲染，提供 SEO 所需 HTML 与元信息。
- Nitro Server Routes：公开内容 API、管理 API、认证和上传服务。
- Tailwind CSS：官网自定义视觉系统。
- Element Plus：仅用于管理后台的表单、表格、对话框和反馈组件。
- Prisma + MySQL 8：数据模型、迁移与持久化。
- Canvas 2D、CSS、IntersectionObserver：首屏粒子连线和滚动动效，不引入大型 3D 引擎。
- Markdown 正文：后台编辑，服务端输出前清理危险 HTML。

不采用独立 NestJS 服务或 Headless CMS，避免首版增加部署节点和维护成本。

## 3. 应用边界与路由

### 3.1 官网

使用 `/zh` 与 `/en` 独立语言路径，根路径根据浏览器语言和已保存偏好跳转。

官网包含：

- 首页：首屏、核心能力、数据指标、解决方案精选、案例精选、新闻精选、公司介绍与联系区域。
- 解决方案列表与详情。
- 客户案例列表与详情。
- 新闻列表与详情。
- 关于我们与联系表单。
- 404 与通用错误页面。

公共布局包含响应式导航、语言切换、移动端菜单和可配置页脚。页脚支持版权文字、ICP 备案号及链接、公安备案号及链接和自定义链接；空字段不输出空元素。

### 3.2 管理后台

后台位于 `/admin`，使用独立布局，不加载官网动效。未登录访问后台时跳转登录页。

后台模块：

- 仪表盘：内容数量、最新留言和快捷入口。
- 站点设置：中英文站点名称、明暗 Logo、Favicon、联系方式、地址、社交链接、默认 SEO。
- 页脚设置：双语版权、备案信息、链接。
- 导航管理：双语名称、链接、排序、显隐。
- 首页管理：各模块双语内容、排序、显隐。
- 解决方案、案例、新闻：列表、新建、编辑、草稿/发布、排序、删除。
- 媒体管理：上传、查看、复制地址和删除未被引用的图片。
- 留言管理：查看和切换已读/未读状态。
- 账号设置：修改当前管理员密码。

首版只有单管理员，不包含角色、权限矩阵、操作审计、多站点或工作流审批。

## 4. 视觉与动效

视觉采用深海军蓝底色、青色主光效、少量紫色渐变和高对比正文。浅色内容区与深色首屏交替，避免整页高亮效果影响阅读。演示 Logo 可替换，不依赖特定品牌素材。

动效包括：

- 首屏 Canvas 数据网格和粒子连线，对指针做轻微响应。
- 标题、按钮和装饰光轨的入场动画。
- 滚动进入视口时的分块揭示。
- 数据指标首次进入视口后的数字增长。
- 卡片悬停时的边框光轨与轻微位移。

动效仅在客户端执行，离开页面时释放观察器和动画资源。系统开启“减少动态效果”时，停用粒子运动、数字滚动和大幅入场动画，直接呈现最终状态。移动端降低粒子数量，不使用影响滚动的视差效果。

## 5. 国际化与 SEO

- 首次访问根路径时优先读取用户手动保存的语言 Cookie；无偏好时读取 `Accept-Language`；无法识别时回退中文。
- 手动切换语言后保存 Cookie，并跳转到当前页面对应的 `/zh` 或 `/en` 路径。
- 导航、按钮、表单提示等界面字符串由 i18n 语言包维护。
- 公司内容使用数据库中的 `zh`、`en` 双语字段，不允许只翻译界面而遗漏内容。
- 某条内容缺少当前语言文本时回退中文；若中文也为空，则不显示该可选区块。
- 各语言页面输出独立 title、description、canonical 和 `hreflang`。
- 提供 Open Graph 元信息、`robots.txt` 和站点地图；草稿、停用内容和后台不进入站点地图。

## 6. 数据模型

Prisma 使用 MySQL 8。双语文本使用结构化 JSON，统一形如 `{ "zh": "…", "en": "…" }`；只读展示通过共享类型解析，写入通过服务端 schema 校验。

主要模型：

- `AdminUser`：邮箱、显示名称、Argon2 密码哈希、创建与更新时间。
- `AdminSession`：会话令牌哈希、管理员、过期时间、创建时间；数据库只保存令牌哈希。
- `SiteSetting`：单例记录，包含默认语言、Logo、Favicon、双语站点名、联系方式、地址、社交链接、SEO 和页脚配置。
- `NavigationItem`：双语名称、URL、排序、显隐。
- `HomeSection`：固定模块类型、双语结构化内容、排序、显隐。模块类型限定为 hero、capabilities、metrics、solutions、cases、news、about、contact。
- `Solution`：唯一 slug、双语标题/摘要/正文/特性、图标、封面、排序、发布状态、发布时间。
- `CaseStudy`：唯一 slug、双语标题/摘要/正文、客户名、行业、成果指标、封面、排序、发布状态、发布时间。
- `NewsPost`：唯一 slug、双语标题/摘要/Markdown 正文/SEO、封面、发布状态、发布时间。
- `MediaAsset`：访问地址、原始文件名、MIME、大小、宽高、创建时间。
- `ContactMessage`：姓名、邮箱、电话、公司、留言、来源语言、已读状态、创建时间。

发布状态统一为 `DRAFT` 或 `PUBLISHED`。公开 API 只返回已发布且发布时间不晚于当前时间的内容。删除操作仅对内容记录生效；被媒体引用的文件不可直接删除。

## 7. API 与数据流

### 7.1 公开接口

- 读取站点设置、导航、首页、解决方案、案例和新闻列表。
- 根据 slug 读取解决方案、案例和新闻详情。
- 提交联系留言。
- 从持久化上传目录读取媒体文件。

列表接口提供分页参数并限制最大页大小。官网 SSR 直接通过服务端内容服务读取数据，避免浏览器暴露管理字段。

### 7.2 管理接口

- 登录、退出、当前会话、修改密码。
- 读取和更新站点、页脚、导航与首页配置。
- 解决方案、案例、新闻的增删改查和发布状态修改。
- 媒体上传、列表和删除。
- 留言列表和已读状态修改。

除登录外，所有 `/api/admin` 接口均要求有效会话。管理写操作使用统一校验、错误格式和事务边界；涉及多表更新时使用 Prisma 事务。保存并发布后，新的 SSR 请求立即读取最新 MySQL 内容，不依赖需要人工清理的前端缓存。

### 7.3 上传

图片保存到应用外的持久化 `storage/uploads` 目录，通过受控媒体路由访问。允许 JPEG、PNG、WebP、SVG 和 GIF；单文件最大 5 MiB。服务端同时检查声明类型和文件签名，使用随机存储名。SVG 不作为可执行 HTML 内嵌，只通过图片地址使用，并清理脚本及外部引用。

## 8. 安全设计

- 管理员密码使用 Argon2 哈希，不记录明文。
- 初始管理员通过受控初始化命令和环境变量创建，不硬编码默认密码。
- 会话使用高熵随机令牌，Cookie 设置 `HttpOnly`、`SameSite=Lax`，生产环境设置 `Secure`。
- 登录与留言接口限流；登录失败返回统一提示，不透露账号是否存在。
- 管理写请求检查会话与 `Origin`，非浏览器服务请求不接受跨站凭据。
- 所有请求体、查询参数和 slug 使用服务端 schema 校验。
- Markdown 渲染结果经过白名单清理，阻止脚本和危险 URL。
- 上传限制类型、大小与文件名，不能通过路径参数遍历文件系统。
- 联系表单包含隐藏防机器人字段，成功提交不泄露内部数据。
- 生产错误响应不返回堆栈、SQL、环境变量或绝对路径。

## 9. 异常与空状态

- API 使用一致的 HTTP 状态码和 `{ code, message, details? }` 错误结构；表单字段错误映射到对应输入项。
- 后台保存失败保留用户已填写内容，上传失败显示原因，登录过期后返回登录页。
- 数据库不可用时记录服务端错误并返回通用 500 页面。
- 无效或不可见内容详情返回 404。
- 官网空列表显示简洁空状态，不渲染破损卡片或空白链接。
- 未配置 Logo 时显示双语站点名称；未配置备案或社交信息时隐藏对应项。
- 联系表单提交期间禁用重复提交，成功和失败都有明确反馈。

## 10. 性能与可访问性

- 官网关键内容 SSR 输出，后台按需加载。
- 图片按显示尺寸生成或选择合适资源，非首屏图片懒加载。
- Canvas 根据设备像素比设置上限，页面不可见时暂停动画。
- 导航、表单、对话框支持键盘操作和可见焦点。
- 文本与背景满足可读对比度，装饰元素不进入辅助技术阅读顺序。
- 表单具有真实 label、错误描述和提交状态。
- 语言切换链接提供对应语言名称，页面根元素输出正确 `lang`。

## 11. 初始化与部署

开发环境需要 Node.js LTS、pnpm 和 MySQL 8；可提供仅包含 MySQL 的 Compose 配置简化本地启动。应用配置通过环境变量提供，包括数据库连接、会话密钥、初始管理员资料和上传目录。项目只提交 `.env.example`，不提交真实密钥。

生产交付为 Nuxt Node.js 构建产物，配合 MySQL 8 和持久化上传目录。部署时执行 Prisma 迁移，再启动应用。升级前由部署方备份数据库和上传目录。

## 12. 验收与验证

实现完成后必须：

1. 执行依赖安装、Prisma 校验与迁移、Nuxt 类型检查、代码检查和生产构建。
2. 通过真实浏览器访问官网，检查桌面和移动端布局、导航、列表、详情、404、语言自动识别和语言偏好记忆。
3. 检查首屏及滚动动效，并验证减少动态效果设置。
4. 使用真实 MySQL 验证管理员登录、退出、修改密码和未登录拦截。
5. 修改 Logo、双语站点名、备案号和页脚链接，确认数据库持久化及官网同步显示。
6. 分别创建草稿和已发布解决方案、案例、新闻，确认草稿不公开、发布内容可见。
7. 上传合法与非法图片，确认媒体校验和上传目录持久化。
8. 提交联系留言，确认后台可见及已读状态可更新。
9. 检查生产 HTML 的语言、SEO、canonical、`hreflang` 和页面主要内容。

不将单纯模块导入或编译成功视为完整验收；关键流程必须通过浏览器、API 和数据库实际联动。

## 13. 首版不包含

- 多管理员、角色权限、审批流和操作审计。
- 在线支付、用户注册、评论、全文搜索引擎。
- 对象存储、CDN、多节点会话和分布式限流。
- 复杂 WebGL/Three.js 场景。
- 多站点和自定义页面拖拽搭建。

这些能力可在首版稳定运行后按实际需求独立扩展。
